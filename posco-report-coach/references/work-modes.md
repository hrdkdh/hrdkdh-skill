# 추가 활용 모드

교재의 방법을 AI 업무로 확장한 기능이다. 사용자의 요청이나 현재 작업에 도움이 되는 모드만 선택한다. 다른 모드를 자동으로 모두 실행하지 않는다.

## 보고 준비 브리프

근거: p.7–15. 작성 시작 전에 대상·목적·필요 결정·독자가 가진 질문·제약·현재 가설을 짧게 정리한다. 불명확한 지시는 확인 질문으로 바꾸되 관련자에게 실제 연락하지 않는다.

산출물: `보고 목적 / 독자 / 핵심 질문 / 현재 가설 / 보유 근거 / 부족한 정보 / 요청할 결정`.

## 고스트팩: 자료 수집용 빈칸 보고서

근거: p.13–15, 20–23. 완성된 보고서의 흐름을 먼저 설계해 불필요한 조사를 줄인다.

- 페이지별로 `답할 질문 / 잠정 헤드라인 / 필요한 증거 / 적합한 표·차트 / 다음 장 연결`을 제시한다.
- 검증되지 않은 헤드라인은 `[가설]` 또는 질문형으로 표시한다. 빈칸을 그럴듯한 숫자로 채우지 않는다.
- 가설을 지지할 자료와 반박할 자료를 함께 정한다. 확인할 수 없는 페이지는 대체 질문을 제시한다.
- 필요하면 수집 목록을 `자료 / 판단 목적 / 정의·범위 / 자료원 후보 / 우선순위`로 만든다. 자료원 후보를 이미 확인한 출처처럼 적지 않는다.

## 경영진용 1쪽 요약

근거: p.6, 18, 20, 24. 핵심 결론, 주요 근거, 대안·위험, 요청 사항을 원문에서 추출한다. 원문의 결론이 미확정이면 잠정 상태를 유지한다.

배치 예: 상단 핵심 결론과 요청 → 중앙 핵심 근거/비교 → 하단 실행 조건·위험·확인사항. 현황 공유라면 요청란 대신 주요 변화와 후속 일정으로 조정한다.

중요 수치·기간·제약을 보존하고 상세 자료는 원문 위치로 연결한다. `1쪽`을 맞추려고 읽을 수 없을 만큼 글자를 줄이지 않는다. 실제 파일을 만들지 않았다면 `1쪽 분량 요약 초안`이라고 부른다.

## 예상 질문과 답변 리허설

근거: p.38–40. 보고받는 사람의 판단을 막는 지점을 질문으로 만든다.

질문 예: 왜 지금 필요한가, 기존 방식으로 안 되는가, 대안은 무엇인가, 근거가 어디까지 검증됐는가, 실패하면 어떤 영향이 있는가, 누가 언제 무엇을 해야 하는가.

`예상 질문 / 현재 근거로 가능한 답 / 근거 위치 / 추가 확인` 형식으로 제시한다. 근거가 없는 질문에 자신감 있는 답을 꾸미지 않는다. 필요하면 30초·1분 구두 요약 초안을 만들되 실제 발표 시간은 검증하지 않은 추정임을 인지한다.

## 주장·근거와 보완 우선순위

근거: p.13–16, 24, 27–28, 45–47. 내용 검토 참고의 근거표를 사용한다. 결정에 가장 큰 영향을 주면서 근거가 약한 주장을 먼저 보완한다. 빠진 자료를 모두 동일한 중요도로 나열하지 않는다.

## 교육·코칭과 문서별 표현 사전

근거: p.38–40, 48–53. 대표 수정 사례를 `원문 / 수정안 / 이유 / 다음에 적용할 원칙`으로 설명한다. 직원 개인의 역량이나 성향을 추정·등급화하지 않는다.

문서 내 고유명사, 약어, 단위, 종결형을 통일하는 작은 용어표를 만들 수 있다. 사용자 요청 없이 다른 직원의 개인 선호를 영구 프로필로 저장하지 않는다.
