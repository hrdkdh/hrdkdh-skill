# 내용·구조·표현 검토

교재 p.6–28, 38–53을 실무 판단 기준으로 재구성했다. 정확성 보존과 계산 규칙은 AI 사용을 위한 보완이다.

## 1. 독자가 해결할 질문부터 찾는다

문서가 누구에게 어떤 판단을 요청하는지 한 문장으로 정리한다. 작성자의 활동 목록과 독자가 알고 싶은 결과를 구분한다.

| 확인할 것 | 문제가 보일 때 할 일 |
|---|---|
| 왜 지금 이 보고가 필요한가 | 달라진 상황·현재 문제·결정 시점을 원문에서 찾아 앞에 배치 |
| 독자가 무엇을 판단해야 하는가 | 승인·선택·지원·인지 중 목적에 맞는 요청을 명료화 |
| 어떤 기준으로 판단하는가 | 비용·효과·기간·위험 등 원문에 있는 기준으로 비교; 없는 기준은 제안으로 표시 |
| 어떤 배경지식을 가진 독자인가 | 비전문가에게 필요한 용어는 설명하고 이미 알려진 배경은 압축 |
| 어떤 제약이 있는가 | 예산·일정·운영 제약을 결론과 연결; 없는 제약은 만들어 넣지 않음 |

상대의 선호는 사용자가 제공한 정보만 적용한다. 취향을 맞추면서 실질적 위험과 반대 근거를 누락하지 않는다. 교재 p.8의 취지는 맥락에 맞춘 설득이며 단일 미적 기준의 강요가 아니다.

## 2. 문서 전체와 한 장을 따로 점검한다

**전체의 흐름(교재 p.18–23, 39)**

- 헤드라인만 추출해 이어 읽는다. `배경 → 문제 → 원인 → 대안 → 권고 → 실행` 같은 연결이 실제 문서 목적에 맞는지 본다.
- 주장보다 근거가 뒤늦게 등장하는지, 같은 내용이 반복되는지, 대안 비교 없이 결론으로 뛰는지 찾는다.
- 상위 주제, 근거, 세부 사례를 구분하고 같은 수준은 같은 기준으로 묶는다. 중복된 분류와 분류 밖의 핵심 항목을 확인한다.
- 결론이 명확하면 결론 우선을 제안한다. 낯선 개념이나 논쟁적인 전제가 핵심이면 필요한 설명을 먼저 둘 수 있다.

**한 장의 정합성(교재 p.22–27, 34)**

- 제목은 주제를, 헤드라인은 그 페이지의 주장을 전달하게 한다. `설비 운영 현황`처럼 제목만 있는 페이지에는 원문으로 뒷받침되는 결론형 헤드라인을 제시한다.
- 본문·표·차트가 헤드라인의 주장과 범위를 실제로 지지하는지 대조한다. 두 비교 항목의 순서도 헤드라인과 맞춘다.
- 한 장에서 함께 다루기 어려운 논점은 나누거나 상위 메시지로 묶는다. 단순히 메시지가 두 개라는 이유로 기계적으로 분할하지 않는다.
- 하단 강조 상자는 본문에서 도출되는 시사점 또는 다음 장 연결에 활용한다. 교재에서는 핵심 결론을 헤드라인에 둔다. 회사 양식이 하단 요약을 요구하면 그 역할을 존중한다.
- 본문에 필요한 증거를 부록으로 밀어내지 않는다. 상세 데이터의 이동 여부는 보고 목적에 따라 정한다. 현황 공유에서는 사실 자체가 본문일 수 있다.

## 3. 사실·해석·제안의 연결을 검사한다

| 구분 | 판단 질문 | 부족할 때의 처리 |
|---|---|---|
| 사실(Fact) | 실제로 어떤 수치·관찰·발언이 제시됐는가 | 위치와 출처 상태를 표시; 근거 자료를 요청 목록에 기록 |
| 해석(Issue) | 어떤 비교·분석을 거쳐 문제가 도출됐는가 | 계산·비교 기준을 설명; 단순 동시 변화는 관련성으로만 표현 |
| 제안(Recommend) | 해석에서 이 행동이 왜 나오는가 | 대안·기대효과·실행 조건·위험을 확인; 제안과 확정을 구분 |

중요 주장에는 필요할 때 다음과 같은 간단한 근거표를 만든다.

`주장 | 원문 위치/자료 | 근거가 지지하는 범위 | 부족한 검증 | 수정 또는 확인 질문`

인과관계는 시간 순서, 작동 이유, 다른 설명을 검토한다. 상관관계나 단순 전후 비교만으로 개선 활동의 효과를 확정하지 않는다. 제한된 표본·특정 현장·선정된 사례의 결과를 전사로 일반화하지 않는다. 반대 사례와 대표성을 함께 확인한다.

## 4. 숫자와 출처를 검산한다

- 단위, 통화, 기간, 대상 범위, 기준 시점, 출처를 확인한다. 비교하는 두 값의 정의와 집계 범위가 같아야 한다.
- 증감률 = `(현재값 - 기준값) / 기준값 × 100`. 기준값이 0이거나 의미가 다른 경우 임의로 적용하지 않는다.
- 비율의 변화는 `%`와 `%p`를 구분한다. 예를 들어 5%에서 4%는 1%p 하락, 상대적으로 20% 감소다. 이 예시는 계산 설명용이며 사용자 실적이 아니다.
- 합계·부분합·본문·표·그래프·요약의 같은 수치를 맞춰 본다. 반올림 차이와 실제 불일치를 구분한다.
- 원자료가 충분하면 계산 과정과 사용 값을 밝힌다. 산식을 확인한 것과 원자료 진위를 검증한 것을 구분한다.
- 출처가 없으면 만들어 붙이지 않는다. 외부 사실 확인을 수행했다면 해당 출처와 시점을 제공하고 원문 정보와 구별한다.
- 최신 목표·전망·효과가 없는 경우 정교한 수치를 임의로 추가하지 않는다. 수치 없이도 가능한 문장 수정은 먼저 한다.

## 5. 문장을 압축하되 의미를 잠근다

교재 p.42–53의 핵심은 짧고 구체적이며 혼자 읽어도 이해되는 문장이다.

1. 의례적 도입과 중복 수식어를 줄인다. 한 문장에 다른 판단이 섞여 있으면 나눈다.
2. 주체를 알고 있을 때 능동형으로 바꾼다. 주체가 없으면 책임자를 발명하지 않는다.
3. 모호한 `크게·상당히·곧`은 알려진 수치·기간으로 구체화한다. 자료가 없으면 관련 확인사항을 남긴다.
4. 약어는 필요할 때 풀어 쓰고, 핵심 명칭·단위·용어는 일관되게 유지한다. 동의어 다양화 때문에 다른 개념처럼 보이게 하지 않는다.
5. 체언 종결과 서술형은 문서 양식에 맞춰 통일한다. 짧게 쓰기 위해 문법·인과·책임·시제를 희생하지 않는다.
6. `할 수 있다·예정·추정·미확인·불가`는 정보다. 삭제해도 원문의 조건과 확실성이 유지되는지 먼저 확인한다.

아래는 모두 새로 만든 예시다.

| 원문 예시 | 개선 예시 | 보존해야 할 의미 |
|---|---|---|
| 향후 추가적인 검토를 진행할 예정임 | 추가 검토 예정 | 완료나 승인으로 바꾸지 않음 |
| 12월 23일 전에는 발송할 수 없음 | 발송 가능 시점은 12월 23일 이후이며 확정일은 확인 필요 | 23일 발송을 약속하지 않음 |
| 생산성이 크게 개선될 것으로 기대됨 | 생산성 개선 기대. 예상 개선 폭과 산정 근거 확인 필요 | 기대를 실적이나 보장으로 바꾸지 않음 |
| 시범 적용 전 5%, 적용 후 4%로 불량률이 감소함 | 시범 적용 후 불량률 1%p 하락(5%→4%). 적용 효과의 인과 검증 필요 | 전후 차이와 인과는 별개 |

수정 결과는 필요할 때 `원문 → 수정안 → 이유`로 보여 준다. 의미가 달라지는 제안은 단순 교정으로 숨기지 말고 별도 제안이라고 표시한다.

## 6. 피드백을 행동으로 연결한다

`가독성이 낮습니다`로 끝내지 않는다. 예: `p.3 하단 표에서 비교 기준이 행마다 달라 대안 비교가 어렵습니다. 동일한 비용·기간·운영 중단 기준을 열로 두고, 원문에 없는 값은 확인 필요로 표시하세요.`

문서가 잘 구성되어 있으면 이를 유지하고 실제 발견한 문제만 제시한다. 모든 기준을 한꺼번에 체크리스트로 출력하지 않는다.
